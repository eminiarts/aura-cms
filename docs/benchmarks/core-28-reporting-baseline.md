# CORE-28 portable reporting baseline

This is decision evidence, not a production service-level objective. It was captured locally on 2026-08-11 with PHP 8.4.7 and disposable database containers. Each deterministic dataset has 80% valid six-decimal values, two equally sized tenants, 20 groups, and 11 unrelated meta values per resource. Statistics were refreshed before measuring. Each cell is p95 milliseconds across ten warm executions; every workload issued one query.

The workload columns are aggregate (`count`, `sum`, `average`, `min`, `max` together), numeric range, grouped sum, and timezone-aware monthly buckets.

At 100k, safe runtime casts fail the accepted interactive threshold of p95 at most 500 ms and at most five times the physical path on every supported engine: MySQL grouped sum is 16.9x physical; MariaDB range is 12.8x and grouped sum is 41.7x. The typed projection remains below 200 ms in every measured workload and makes indexed numeric ranges 14.9x to 437.5x faster than the physical baseline.

The exact 10k and 100k p95 results and summarized query plans are in `core-28-reporting-baseline.json`. Raw `EXPLAIN` JSON is deliberately generated by the opt-in harness rather than committed with random fixture table names.

## Reproduce

Run `tests/Feature/Reporting/ReportingDatabaseMatrixTest.php` first against SQLite and configured MySQL, MariaDB, and PostgreSQL connections. Then run the opt-in benchmark separately for each engine so concurrent workloads do not distort timings:

```bash
AURA_REPORTING_BENCHMARK=1 \
AURA_REPORTING_DRIVER=pgsql \
AURA_REPORTING_ROWS=100000 \
AURA_REPORTING_ITERATIONS=10 \
AURA_REPORTING_BENCHMARK_OUTPUT=/tmp/core28-pgsql-100000.json \
AURA_TEST_POSTGRES_DATABASE="$DATABASE" \
AURA_TEST_POSTGRES_HOST="$HOST" \
AURA_TEST_POSTGRES_PORT="$PORT" \
AURA_TEST_POSTGRES_USERNAME="$USERNAME" \
AURA_TEST_POSTGRES_PASSWORD="$PASSWORD" \
php -d memory_limit=2G vendor/bin/pest --no-coverage --compact \
tests/Benchmarks/Reporting/PortableReportingBenchmark.php
```

Use the corresponding `AURA_TEST_MYSQL_*` or `AURA_TEST_MARIADB_*` variables for those engines. SQLite needs no connection variables. These local single-host numbers compare paths; they are not capacity, concurrency, cold-cache, network, replica-lag, or production-hardware claims.
